The inventory records all 104 command records under the goal-11 roots plus discovery, and assigns the remaining 66 roots individually (48 to g10-1 and 18 to g12-1). Counts are capture observations, not future gates.

Inventory discovery used only `orca agent-context --json`; the read-only version-matched guide command `orca skills get orca-cli --json` was also used. Each Orca call used a fresh temporary `QUIRKY_HOME`. The capture keeps each command's words, summary, usage, flags, notes, and other schema fields. CI reads the frozen capture and never invokes Orca. Markdown and JSON are data, never command sources. The runner uses compiled references in `cli-table.ts`, and behavioral argv comes from compiled probe declarations.

Each primary captured command has exactly one row, with ID formed by joining its command words using hyphens. `covered` means the Check cell names behavioral receipts/assertions; it does not claim a historical run. `mapped-only` means the live catalog can prove the mapping but a named exercise remains. ## Scope notes

- Local `project list`, `setups`, and `setup-*` commands map to `repo` operations. `project-remote-hosts` excludes per-host selectors and setup state under BRIEF.md:67–68; no separate local project identity or store migration is proposed.
- The `serve` startup gap is **Expose owned foreground headless startup with JSON readiness**. CLI autostart and a headless daemon entrypoint are not equivalent to an owned foreground command with JSON readiness. This item does not invoke `daemon restart`.
- File diff, open-changed, and open-render gaps are **Prove file and review CLI targeting in the real UI**. The candidate UI commands open a combined Review tab; the planning evidence does not establish Orca's per-file/background-tab/focus contract. This is not a claim that Git diff is absent.
- Agent launch covers terminal launch, not native chat. Codex hook setup, status and removal run only in the owned home and preserve a user-owned hook. Managed-account coverage is Claude/Codex local stand-in sign-in and removal; OpenCode/Devin selection is excluded by a scope inference, not a product capability assertion.
- Terminal IDs are Quirky session IDs, not Orca handles. `agent-status wait --until exited` proves exit only; idle semantics differ from Orca's TUI-idle wait. `agent-status send` exists, but raw terminal-send receipts do not prove agent prompt delivery.
- Worktree creation uses `--base`; removal may retain a branch at an explicit head. `accounts list` is not the usage report. Normal CLI results are direct JSON values; Ask output is JSONL. Aliases are catalog metadata: `loop` resolves to `loops`, and `file` resolves to `editor`.
- Browser roots, including `open-url`, are delegated to g10-1. Ledger, Heimdall, reference search, emulator, computer use, host/environment management, session search, and other residual roots are delegated individually to g12-1 in the capture; no delegated result is duplicated or treated as a pass here.


## Running the rehearsal

```sh
bun scripts/parity/cli.ts --json
bun test scripts/parity/cli-table.test.ts
bun test scripts/parity/cli-failures.test.ts
bun test scripts/parity/cli.test.ts
bun run typecheck
```

The rehearsal owns its temporary home, Git repositories, daemon, PTY host, and provider stand-ins. It never invokes Orca or a real provider. It emits one final JSON report after cleanup; catalog evidence never upgrades a mapped-only row to behavioral coverage. File checks observe daemon buffers and layout, not rendered focus.

Children use explicit local JSON mode, an owned no-profile shell, fixture-only agent discovery, a narrow PATH, a Keychain denial shim, and a non-loopback fetch tripwire loaded through `BUN_OPTIONS`. Startup proves the tripwire before starting the daemon; the final check rejects any further egress or Orca call and any unexpected Keychain command. Sign-in stand-ins write no access token. CLI autostart points at an absent owned entry so a daemon-death race fails instead of starting a replacement. The process-scope adapter supplies an explicit environment to implicit Bun subprocess calls: Bun 1.4.0 otherwise uses its startup environment snapshot.

Work aborts by 340 seconds, with 20 seconds reserved for cleanup. Command output is bounded at 16 MiB stdout and an 8 KiB stderr tail. Each ordinary command has a 15-second deadline.

Remaining shared table/registry follow-ups are serialized: **Complete orchestration CLI lifecycle exercises** → **Expose owned foreground headless startup with JSON readiness** → **Expose owned background-service and restore controls** → **Prove file and review CLI targeting in the real UI**. The last waits for g9-1 and g10-1. These titles are references, not invented queue IDs.
