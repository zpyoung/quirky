The source schema was version 1; Orca reported 322 total commands across 81 root words. The inventory records all 104 command records under the goal-11 roots plus discovery, and assigns the remaining 66 roots individually (48 to g10-1 and 18 to g12-1). Counts are capture observations, not future gates.

Inventory discovery used only `orca agent-context --json`; the read-only version-matched guide command `orca skills get orca-cli --json` was also used. Each Orca call used a fresh temporary `QUIRKY_HOME`. The capture keeps each command's words, summary, usage, flags, notes, and other schema fields. CI reads the frozen capture and never invokes Orca. Markdown and JSON are data, never command sources. The runner uses compiled references in `cli-table.ts`, and behavioral argv comes from compiled probe declarations.

Each primary captured command has exactly one row, with ID formed by joining its command words using hyphens. `covered` means the Check cell names behavioral receipts/assertions; it does not claim a historical run. `mapped-only` means the live catalog can prove the mapping but a named exercise remains. A `gap` names missing behavior and a follow-up; partial candidates are catalog-checked, never counted as equivalent behavior. Every exclusion records its scope source. Delegated root rows identify ownership only and never pass as goal-11 behavior.
An optional `observe` clause links renderer-only evidence for selected rows; it is separate from behavioral checks and never changes a row's disposition or the core parity verdict.

## Scope notes

- Local `project list`, `setups`, and `setup-*` commands map to `repo` operations. `project-remote-hosts` excludes per-host selectors and setup state under BRIEF.md:67–68; no separate local project identity or store migration is proposed.
- `serve` never borrows or stops a daemon it did not start. It leaves the PTY host and its terminal sessions running, as Orca's service leaves its terminal daemon. It does not invoke `daemon restart`.
- Service installation/status/removal and host-wide restore resume are exclusions, not successful exercises. Detached autostart does not supply login startup or crash supervision. The conclusion that no owner need for a managed login service is established is item g11-5's inference from the owner record, not an owner quotation or an explicit prohibition.
- Renderer observations cover editor placement and combined Review targeting without closing the three presentation gaps. Focused editor open selects the destination workspace tab but does not navigate the current window; Review activates one combined tab and lacks explicit background, edit/diff/both, and staged/unstaged selection modes. Product follow-ups are **Navigate the selected window for editor open focus** and **Provide explicit background Review presentation**.
- Agent launch covers terminal launch, not native chat. Codex hook setup, status and removal run only in the owned home and preserve a user-owned hook. Managed-account coverage is Claude/Codex local stand-in sign-in and removal; OpenCode/Devin selection is excluded by a scope inference, not a product capability assertion.
- Terminal IDs are Quirky session IDs, not Orca handles. `agent-status wait --until exited` proves exit only; idle semantics differ from Orca's TUI-idle wait. `agent-status send` exists, but raw terminal-send receipts do not prove agent prompt delivery.
- Worker terminal capture retains the newest bounded history/screen tail and pages forward within it. Consumed live screen text can change; continuing then reports `source_changed`. This is not an immutable live stream or an atomic terminal snapshot, and does not establish remote-host parity.
- Worktree creation uses `--base`; removal may retain a branch at an explicit head. `accounts list` is not the usage report. Normal CLI results are direct JSON values; Ask output is JSONL. Aliases are catalog metadata: `loop` resolves to `loops`, and `file` resolves to `editor`.
- Browser roots, including `open-url`, are delegated to g10-1. Ledger, Heimdall, reference search, emulator, computer use, host/environment management, session search, and other residual roots are delegated individually to g12-1 in the capture; no delegated result is duplicated or treated as a pass here.

The core CLI rehearsal owns its temporary home, Git repositories, daemon, PTY host, and provider stand-ins. It never invokes Orca or a real provider and emits one final JSON report after cleanup; catalog evidence never upgrades a mapped-only row to behavioral coverage. The core report remains renderer-free: linked file observations are optional pointers with `executed:false`; they never enter ordinary checks, proofs or `parityComplete`. The separate file runner reports only linked observations, and success does not promote `file-open-render`, `file-diff` or `file-open-changed` from `gap`.

Children use explicit local JSON mode, an owned no-profile shell, fixture-only agent discovery, a narrow PATH, a Keychain denial shim, and a non-loopback fetch tripwire loaded through `BUN_OPTIONS`.
