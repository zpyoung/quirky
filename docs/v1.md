# Quirky v1

v1 is the smallest Quirky you can use for a day of agent work on macOS. You add a repo, create
worktrees, and run shells and coding agents in terminals that survive closing the app. Agents
show working, waiting and done states, and notify you when they finish. You review and commit
changes in a diff view, answer `quirky ask` questions from agents, and run background Claude
sessions with no terminal. It implements the design in [architecture.md](architecture.md) on Bun
and Electrobun.

## What v1 leaves out

These are later milestones; the API leaves room for them.

- **Not built yet:** the embedded browser, the editor (v1 has a diff view only), hosting pages
  (PRs, issues, checks), the AI vault, accounts and usage, automations, orchestration, Heimdall,
  the sitter, objectives, loops, the ledger, handoff, the terminal dock, session info, and mobile.
- **Agents:** five are supported (shell, Claude Code, Codex, OpenCode, Gemini), not 25+. Status
  hooks exist for Claude and Codex only.
- **Platforms:** macOS only.
- **Desktop window and CLI:** both use the daemon's WebSocket. The unix socket for the CLI comes
  later.
- **Terminal attach:** replays recent raw output instead of using a screen snapshot. History beyond
  1 MiB stays on disk without paging.

## Layout

```
packages/protocol   shared types, frame codecs, the WebSocket client, daemon discovery (./node)
packages/pty-host   quirky-pty: owns PTYs, the on-disk logs and the screen emulators
packages/daemon     quirkyd: the API, stores, git, sessions, hooks, asks, structured sessions
packages/ui         the React single-page app, built to packages/ui/dist
packages/cli        the quirky command
apps/desktop        the Electrobun shell
```

All TypeScript runs on Bun 1.4. Tests use `bun test`. Packages import each other only through
`@quirky/protocol`; the daemon talks to the PTY host only over its socket.

## Files and environment

`QUIRKY_HOME` (default `~/.quirky`, mode 0700) holds everything:

| Path | Owner | Contents |
| --- | --- | --- |
| `runtime.json` | quirkyd | `RuntimeInfo` (see `packages/protocol/src/node`), mode 0600, removed on clean exit |
| `quirky.db` | quirkyd | SQLite (`bun:sqlite`): repos, sessions, asks, structured messages, settings |
| `pty.sock`, `pty.token`, `pty.pid` | quirky-pty | the control socket, its auth token (0600) and pid |
| `sessions/<sessionId>/output.log` | quirky-pty | raw output; rotates to `output.1.log` at 16 MiB |
| `hooks/claude-settings.json` | quirkyd | the `--settings` file that adds Quirky's Claude hooks |
| `bin/quirky-hook`, `bin/quirky` | quirkyd | shims put on every session's PATH |
| `logs/daemon.log`, `logs/pty-host.log` | each process | stdout and stderr |

Environment variables:

| Variable | Read by | Meaning |
| --- | --- | --- |
| `QUIRKY_HOME` | all | the state directory |
| `QUIRKY_DAEMON_ENTRY` | protocol/node (`ensureDaemon`) | the daemon script to spawn; defaults to `packages/daemon/src/main.ts` |
| `QUIRKY_PTY_HOST_ENTRY` | quirkyd | the PTY host script; defaults to `packages/pty-host/src/main.ts` |
| `QUIRKY_UI_DIR` | quirkyd | the built UI to serve; defaults to `packages/ui/dist` |
| `QUIRKY_CLI_ENTRY` | quirkyd | the CLI script the `bin/quirky` shim runs; defaults to `packages/cli/src/main.ts` |
| `QUIRKY_PORT` | quirkyd | fixed port for tests; default is a random free loopback port |

Processes are started with `process.execPath` (the running Bun) so a packaged app needs no Bun
on PATH. The daemon and the PTY host detach from whoever started them and keep running when the
window closes.

Sessions get `TERM=xterm-256color`, `COLORTERM=truecolor`, `QUIRKY_HOME`, `QUIRKY_SESSION_ID`,
`QUIRKY_WORKTREE_ID`, `QUIRKY_HOOK_URL` (`http://127.0.0.1:<port>/hook`) and `QUIRKY_HOOK_TOKEN`,
with `<QUIRKY_HOME>/bin` first on PATH.

## Daemon behaviour

- **HTTP server:** one Bun server on 127.0.0.1. It handles `GET /health` (returns
  `{ ok, pid, daemonVersion }`, no auth), the WebSocket at `/rpc?token=`, `POST /hook/<agent>`,
  and the static UI at every other GET path, with `index.html` as fallback.
- **One instance per home:** a second daemon started on the same home exits if the first is
  healthy.
- **Startup:** connects to the PTY host, or starts it if it doesn't answer. It then reconciles
  stored sessions with the PTY host's list, marking missing ones `exited`.
- **Agent launch:** each agent runs under the user's login shell (`$SHELL -l -c 'exec …'`), so
  CLIs installed through Homebrew, nvm or similar resolve as they do in Terminal. A shell session
  is `$SHELL -l`. The commands and how each takes its prompt follow Orca's
  `src/shared/tui-agent-config.ts`.
  - **Claude:** `claude --settings <QUIRKY_HOME>/hooks/claude-settings.json [prompt]`. The settings
    file maps `UserPromptSubmit` and `PreToolUse` to working, `Notification` to waiting and `Stop`
    to done, each by running `quirky-hook claude`. The user's own `~/.claude` config is never
    edited.
  - **Codex:** `codex -c 'notify=["<QUIRKY_HOME>/bin/quirky-hook","codex"]' [prompt]`. A notify
    call means the turn is done.
- **`quirky-hook <agent>`:** a POSIX sh script. It POSTs its stdin (Claude), or its last argument
  (Codex), to `$QUIRKY_HOOK_URL/<agent>?session=$QUIRKY_SESSION_ID` with the hook token header.
  It always exits 0 quickly, so a stopped daemon never blocks an agent.
- **Status transitions:**
  - A transition to `done` or `waiting` emits a `notify` event: the title is the worktree name,
    and the body reads "Claude finished" or "Claude needs input".
  - If no `desktop` client is connected, the daemon also shows the notification with
    `osascript -e 'display notification …'`, subject to the `notifications` setting.
  - Process exit sets `exited`.
- **`terminal.send`:**
  - **Agents:** the text goes as a bracketed paste (`ESC[200~ … ESC[201~`), then `\r` as a
    separate write about 300 ms later.
  - **Shells:** the text goes as typed, followed by `\r`.
- **Asks:**
  - Stored in SQLite, so a pending ask survives a daemon restart.
  - `ask.wait` resolves as soon as the ask is answered, cancelled or declined.
  - A created ask emits `ask.created` and a `notify` event.
- **Structured sessions (Claude only):**
  - Use `@anthropic-ai/claude-agent-sdk` with `pathToClaudeCodeExecutable` set to the user's
    `claude`, found through the login shell. `cwd` is the worktree.
  - Every SDK message is journaled as a `StructuredMessage`.
  - A tool permission request becomes an ask with allow, deny and always-allow options, answered
    like any other ask.
  - `structured.send` adds a user turn.
  - Status goes `working` while a turn runs and `done` when it ends.

## PTY host behaviour

- **Terminals:** spawned with `Bun.spawn({ terminal })`, which needs no native module.
- **Per session:**
  - The output log on disk.
  - A 1 MiB in-memory tail for `subscribe` replay.
  - An `@xterm/headless` terminal with 200 lines of scrollback for `read`. The tracked `alt` flag
    reports the alternate screen.
- **Exited sessions:** stay listed, with their output, until `forget`.
- **Lifetime:** survives the daemon disconnecting or restarting. Its own exit kills its sessions.

## UI

- **Connection:** reads the token from `location.hash` (`#token=…`), connects to
  `ws://<location.host>/rpc?token=…`, and subscribes to events. It reconnects with backoff when
  the daemon restarts.
- **Layout:**
  - **Left sidebar:** repos and their worktrees, each worktree with a status dot (the most urgent
    session status: waiting, working, done, running). It also has add-repo (a path field), new
    worktree, and remove worktree with a confirmation.
  - **Main area:** the selected worktree's sessions as tabs, with a new-session menu (Shell,
    Claude, Codex, OpenCode, Gemini, Claude in background) and an optional initial prompt.
  - **Right panel (toggle):** source control. It shows changed files grouped staged and unstaged,
    with stage and unstage controls, a side-by-side diff (`@codemirror/merge`, read-only), and a
    commit message box.
  - **Asks:** pending asks show as cards over the main area, until answered or dismissed (which
    declines).
- **Terminals:** xterm.js with WebGL and fit, `scrollback` from settings (default 2000). Only the
  active tab is mounted, and switching tabs disposes the old terminal and reattaches the new one.
- **Structured sessions:** render as a transcript (messages, collapsed tool calls), with an input
  box for follow-ups.
- **Toasts:** `notify` events show as in-app toasts.
- **Theme:** dark, plain CSS, no CSS framework.

## CLI

`quirky [--json] <command>`. It connects with `connectDaemon({ role: 'cli' })`, which starts the
daemon if needed. Output is human-readable, or JSON with `--json`. The worktree defaults to
`$QUIRKY_WORKTREE_ID`, else the worktree containing the cwd. The session defaults to
`$QUIRKY_SESSION_ID`.

- **Status:** `status`
- **Repos:** `repo add <path>`, `repo list`, `repo rm <repoId>`
- **Worktrees:** `wt list [--repo <id>]`, `wt create <repoId> <name> [--base <ref>]`,
  `wt rm <worktreeId> [--force]`
- **Sessions:** `session list [--worktree <id>]`, `session new --agent <kind> [--worktree <id>]
  [--prompt <text>] [--background]`, `session close <id>`
- **Terminals:** `term read [<sessionId>] [--lines N]`, `term send <sessionId> <text> [--enter]`
- **Asks:** `ask --spec <json|@file> [--timeout-ms N]`, `ask wait --id <askId>`, `ask cancel --id <askId>`
- **Desktop:** `open` launches the desktop app if installed

`quirky ask` keeps the shape of `orca ask`, so agent skills written for it work unchanged:

- It prints `{"status":"registered","askId":…}` first.
- It then long-polls `ask.wait` in 60 s calls until a terminal status or `--timeout-ms`.
- It prints the final envelope as one JSON line and exits 0 for every registered outcome.

## Desktop shell

- **Startup:** `ensureDaemon()`, then one window loading `http://127.0.0.1:<port>/#token=<token>`.
- **Daemon connection:** a `desktop`-role client subscribed to events.
  - Turns `notify` events into native notifications.
  - Sets the dock badge to the number of waiting sessions plus pending asks.
- **Tray:** a menu with Show Quirky and Quit Quirky. Quit Quirky stops the window, never the daemon.
- **Closing the window:** quits the shell, while the daemon and sessions keep running.
- **Packaging:** the packaged app bundles the daemon, PTY host, CLI and UI. It points the
  `QUIRKY_*_ENTRY` variables and `QUIRKY_UI_DIR` at them.

## Running it

- `bun install` once.
- `bun run dev` builds the UI and opens the app in development mode.
- `bun run build` produces the packaged app under `apps/desktop/build/`.
- `bun run daemon` runs the daemon in the foreground. The UI is then also reachable in a browser
  at the URL it prints.
- `bun test` runs every package's tests.

**Tests never touch the real `~/.quirky`, `~/.claude` or `~/.codex`.** Every test that starts a
process sets `QUIRKY_HOME` to a fresh temporary directory and kills what it started.
