Quirky ships **skills** that agents install into their skill directories. Public install packages are **hybrid discovery stubs**: short `SKILL.md` files that tell the agent _when_ to engage Quirky and how to load the full guide from the running CLI. Command flags live in the binary so they cannot drift from the app version.

## Installable Quirky skills

Use `npx skills add` with the public Quirky repo and the skill name. Default agent setup usually installs `quirky-cli`, `computer-use`, and `orchestration`.

| ------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| [`quirky-cli`](#quirky-cli)                             | `npx skills add https://github.com/stablyai/orca --skill quirky-cli --global`               | Worktrees, terminals, files, automations, embedded browser.   |

## Hybrid stubs vs the live guide

After `npx skills add`, agents see a short stub that says:

1. Resolve the CLI executable for this session (`QUIRKY_CLI_COMMAND`, `quirky-dev`, Linux `quirky-ide`, else `quirky`).
2. Load the full guide: `quirky skills get <topic>` (or `--full` for the long guide).
3. Prefer `--json` and do not invent flags from memory.

```bash
quirky skills list
quirky skills get quirky-cli
quirky skills get orchestration --references
quirky skills get orchestration --reference recovery-and-cleanup
quirky skills get orchestration --full
quirky skills get quirky-linear --json
```

A guide's action gates name conditional references. `--reference <name>` prints one of them alone, so an agent pays for the kernel plus that document instead of the whole package; `--references` lists the names. The name may be bare (`recovery-and-cleanup`) or spelled as the guide writes it (`references/recovery-and-cleanup.md`). `--full` still prints the kernel plus every reference.

Add `--json` when an agent needs deterministic output for automation. `skills show` is an alias for `skills get`.

## Keep skills up to date

When Quirky ships a newer skill package than the one installed globally, the app can:

- Show an **update available** nudge for skills Quirky installed (and **Needs attention** when a copy is out of date somewhere the updater cannot safely rewrite).
- Open **Update skills** — list of placements and skip reasons, with a checkbox per skill. Quirky's own skills start ticked; a same-named skill installed from somewhere else is marked **Not from Quirky** and starts unticked. The selected skills are reinstalled headlessly (no embedded terminal) with **`npx --yes skills@1.7.2 add https://github.com/stablyai/orca/tree/<commit> --skill <name>… --global -y`**, pinned to the commit the running Quirky build was made from (so it works on hourly, daily, RC and stable builds alike) and to a known skills CLI version.
- Keep the run in the **background**: closing the dialog does not cancel it. A status-bar segment shows progress (spinner while running, brief success check, persistent failure until you act). Click the segment to reopen the dialog.
- Surface freshness on **Settings → Agents** for installed skills (global install rail), including **Details** when a row needs review.

Manual equivalent (desktop Settings shows the same pinned form for the running build):

```bash
npx skills@1.7.2 add https://github.com/stablyai/orca/tree/<commit> --skill quirky-cli --skill orchestration --global
```

On headless hosts (SSH, containers, CI, `quirky serve`) with no Settings UI, use the local CLI wrappers — they resolve the same `npx` commands, add non-interactive flags, and do **not** need a running Quirky runtime:

```bash
quirky skills install                                      # list installable names
quirky skills install --skill quirky-cli --skill orchestration
quirky skills install --skill quirky-cli --agent claude-code,codex
quirky skills install --all --dry-run
quirky skills update --all
quirky skills update --skill quirky-cli --dry-run
```

- Default scope is **global** (`--global`); pass `--local` for the current project only.
- `install` targets agents Quirky detects on the host (plus the shared `.agents/skills` directory). Use `--agent <name>[,<name>…]` or `--agent universal` to override; if no agent is detected, `--agent` is required.
- `update` runs the same pinned `skills add` as `install`. With no agent detected it targets only `.agents/skills` instead of refusing.
- `--dry-run` prints the resolved command; `--json` is only valid with listing / `--dry-run`.

Prefer the in-app updater when Quirky offers it so the same global placements the app scanned get rewritten. Rows marked **Skipped** explain why that skill cannot be updated automatically (for example a read-only folder or a link pointing outside Quirky's skill folders) — fix the placement, then re-check.

## Delete from the Skills page

To remove a scanned skill, open its actions menu and choose **Delete…**. For several skills, open the page's **More actions** menu, choose **Delete skills…**, and select the eligible results. Quirky explains why a copy cannot be deleted—for example because it is bundled, plugin-managed, read-only, or outside a removable skill folder—before you confirm.

## quirky-cli

```bash
npx skills add https://github.com/stablyai/orca --skill quirky-cli --global
```

After install, load the version-matched command guide with `quirky skills get quirky-cli`. See [Quirky CLI](/docs/cli/overview).

## orchestration

```bash
npx skills add https://github.com/stablyai/orca --skill orchestration --global
```

Use this when an agent should coordinate other agents through Runs, tasks, supervised workers, and decision gates. See [Orchestration](/docs/cli/orchestration). Always load `quirky skills get orchestration --full` before mutating orchestration state — the legacy `orchestration run` command is retired.

## computer-use

```bash
npx skills add https://github.com/stablyai/orca --skill computer-use --global
```

Use this when an agent needs to inspect and operate local desktop app windows. See [Computer use](/docs/cli/computer-use).

## quirky-linear

```bash
npx skills add https://github.com/stablyai/orca --skill quirky-linear --global
```

Agents should load `quirky skills get quirky-linear` before mutating tickets. Covers `issue --full`, `save-issue`, `list-issues`, relations, completion attach+comment flow, and untrusted-ticket rules. Existing `linear-tickets` installs still resolve. See [CLI reference → Linear](/docs/cli/reference#linear).

## quirky-emulator

```bash
npx skills add https://github.com/stablyai/orca --skill quirky-emulator --global
```

Use this when an agent should control an iOS Simulator from inside Quirky through `quirky emulator` commands.


Use for adb-connected Android AVDs/devices: list/boot, tap/swipe/type, hardware buttons, install/launch, permissions, accessibility tree, logcat. Load details with `quirky skills get quirky-emulator-android`.

## Discovery sources

Quirky's skill UI scans installed skill homes for Claude, Codex, Agent Skills, and **OMP** (`~/.omp/agent/skills`), so skills placed there show up without a manual symlink.

## Add your own skills

Any repo with a `skills/<name>/SKILL.md` file can be installed via `npx skills add`. Point your agent at internal repos to give it company-specific powers.

## MCP servers

Model Context Protocol (MCP) servers expose external tools to compatible agents. Register MCP endpoints under [Settings → Integrations → MCP](/docs/settings); those tools appear inside agent CLIs that support MCP.
