# Quirky mobile companion

## Status & amendments

## Purpose and conceptual model
A fork of Orca's Expo phone application is a direct, pinned-key, encrypted client of Quirky's public API. Native screens own pairing, credentials, home/settings and diagnostics. Desktop-built workspace/session pages run in an isolated native WebView, with no socket or credential access; a bounded granted bridge proxies calls to the native authenticated client. A compatible page update is downloaded and verified before replacing the prior complete generation.

## Scope and non-goals
This item unions queue parts1/2: mobile.md Pair the phone, First-run onboarding, Home/host cards, Phone settings, Credential storage, Direct client, Page bundle, Host workspace list, Session screen and Terminal streaming. No source control, files/explorer, Tasks, Accounts or Agent History routes. Home cross-feature links must not lead to nonexistent screens. Browser and Markdown session tabs can use installed public APIs when their capabilities are present; absence yields an explicit unavailable action, not fake success.

Locked exclusions: no upstream relay/cloud accounts, legacy handshake, runtime grants/delegation, upstream distribution/update/feedback services. Signed distribution is already queued as sb-mobile-install-links. Interactive structured chat and voice/dictation conflict with architecture.md145–178 and roadmap.md175–181: retain terminal agents and answer real ask cards from the phone; do not introduce interactive structured launches or native chat. One follow-up before landing records the excluded native-chat/voice/settings integration flows and required ruling. Notification preference/permission settings may be stored locally; do not claim remote push delivery before its separately owned service exists. Android/Linux/Windows execution is deferred platform work; portable Android native shell source may be retained from upstream with notice, but no Android pass is claimed.

## Data flow
QR scan, confirmed quirky://pair link or pasted code parses the exact mobile offer, then opens its /rpc endpoint. Native client generates fresh ephemeral key/nonce, validates the strict ready transcript and pinned public key, seals bearer authentication, checks authenticated transcript proof, and only then publishes connected state. Metadata stores contain no token. Native SecureStore owns credential writes/read/deletion; unavailable keychain is distinct from missing credential. Successful authenticated pairing updates the host by public-key identity without duplicating cards, records host info, latches v2 and runs outstanding onboarding steps. No legacy fallback exists even before the latch.

Opening a host loads bundle manifest over the authenticated socket, checks route/grant/asset budgets, stages assets, verifies length/hash/build ID and atomically activates a complete generation. The native shell serves only that generation from its per-mount isolated custom origin and installs the bounded bridge. The page receives safe host/route/preferences, never token/secret key. RPC/events/terminal bytes travel through the native client; method allowlisting and route grants apply on both sides. New page generations cannot widen native privileges.

## Decisions locked (gray-area answers)
- Visual layout: native host cards and sheets; compact responsive workspace list and session tab strip/dock; scrollable sheets remain reachable at320px width and keyboard height. Wide layouts expose a collapsible/resizable persisted sidebar. Status, title and branch precede optional properties.
- Loading/empty/error: explicit connecting/downloading/opening, no-host/no-worktree/no-tab states and retry paths. Revoked hosts show Pairing invalid and disable mutations; disconnected cached content is visibly stale. A page update failure preserves last good complete generation, not partial bytes.
- Interaction: link pairing requires confirmation; scan/paste validates before connection; remove requires confirmation and secure deletion or a visible retry-cleanup record. Delete workspace uses existing confirmation API, never bypasses it. Destructive bulk tab actions respect existing guards.
- Auth/versioning: direct v2 only; pinned key; persistent per-key v2 latch; no secret-bearing errors/logs. Phone is not a trusted local desktop client. Quirky JSON-RPC and terminal frames remain authoritative; do not port Orca method aliases.
- Data/idempotency: host identity is pinned desktop key, re-pair updates credentials without duplicate cards, friendly name retained. Metadata persists separately from secrets. Removal deletes cached client, latch association as appropriate and token, preserving cleanup retry if keychain is unavailable. Cache max6hosts LRU.
- Errors/retry: pairing overall25s, socket connect12s/handshake5s/request30s; reconnect0.5/1/2/4/8/15/30/60s then slow90s trickle. Auth failure stops retries until re-pair. Background pauses owned activity; foreground resumes; liveness idle20s/probe8s. Never replay uncertain mutations automatically.
- Settings/mapping: terminal50/75/100/125/150/200% text, autocomplete off, custom shortcuts; default session view terminal under locked architecture; terminal links choose supported desktop browser or phone browser; auto-restore null/1/5/30minutes is daemon-owned with a narrow phone API. Unsupported voice/push/distribution capabilities are truthful and disabled rather than routed to Orca services. Diagnostics last200entries perhost and fully redacted copy, no upstream submission.

## Key decisions & rationale
Recommended: selectively fork upstream Expo/native shell boundaries and implement Quirky consumers, preserving upstream MIT notice. Rejected: copying all upstream app (imports193 incompatible RPC methods, relay/legacy/cloud services and excluded screens); new browser-only app (violates Expo/native secure storage/page-shell behavior); widening daemon UI listener (violates daemon D5).

## Technical decisions and shared contracts
### Ownership and entrypoints
`apps/mobile` is the Expo app. Parent commits `apps/mobile/src/contracts.ts` before workers. Native component owns App.tsx/app.json/package.json/tsconfig/native entry, src/native/**, src/storage/** and src/transport/**. Pages component owns src/pages/** plus web-entry/**. Bundle component owns src/shell/**, modules/**, scripts/build-pages.ts, existing quirky.mobile plugin API/CLI/manifest/auth additions and tests, and desktop bundle packaging integration. Parent owns root scripts/lock/typecheck integration, shared contracts, specs/decisions/native scenarios and cross-component adapters only after workers return.

### Native/page contracts
The committed contracts are authoritative exact signatures. MobileRpc.call(method,params,options) returns typed caller-selected result with requestId/timeout; onEvent/onStream/onState return unsubscribe, close disposes. MobileRuntime owns hosts/preferences/native actions/RPC acquisition and safe navigation. HostPageShell receives runtime,hostId,route,onNavigate. PageApp receives a MobilePageBridge exposing safe call/events/streams/storage/native actions; it has no websocket constructor or credential DTO. Bundle manifest v1 has shellVersion1, buildId, routes, assets(path/bytes/sha256/contentType), totalBytes; max256assets/32MiBtotal/10MiBasset/64routes. Routes are only workspace and session for this item; grants literal from committed types.

### Public API growth
Extend existing quirky.mobile built-in, not a new privileged service. `bundleManifest {}` returns manifest/chunkBytes/rangeBytes; `bundleChunk`/`bundleRange {buildId,path,offset}` return bounded base64 content/eof/hash, range optionally gzip. Local/phone calls use same schemas/CLI. Bundle root is packaged plugin asset dir, never caller supplied. Narrow phone preferences read/update owns autoRestoreFit only; no generic unrestricted configure. Extend literal mobile allowlist only for methods actually used by shipped pages and parameter-specific restrictions; no wildcard/admin/settings/agent bypass. Terminal clear/display-mode or other missing operations must be public plugin-owned methods respecting mobile lease; no private daemon imports.
