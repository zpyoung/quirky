# Paired-owner session features: technical map

Status: approved autonomously under LOOP; combined Codex specification review required before implementation. Logic: [logic.md](logic.md).

## Architecture
Implements [S1–S7](logic.md#behavior-and-acceptance-scenarios) in the three existing built-ins. Accounts owns scoped API routing and its window store; Vault owns production contribution discovery/forwarding and host-qualified actions; Handoff owns destination/probe/launch/delivery/lineage. Protocol supplies data-only owner/session reference types, already exported through runtime-owner. No new daemon kernel service or transport.

## Contracts & interfaces
For [S1–S7](logic.md#behavior-and-acceptance-scenarios):

**CONTRACT:** `OwnerSessionHostRef = {hostId:string, identity:OwnerHostIdentity, runtime:OwnerRuntimePin}`. The host ID must equal identity.hostId. Every incoming reference is untrusted until matched exactly against canonical current registration. Full pin comparison includes id, endpoint, grantId, hostId and generation. Every runtimeCall supplies both pins and selects the saved runtime by exact ID, not a friendly-name prefix. Never accept caller credential material.

**CONTRACT:** `OwnerSessionWorkspaceRef = {owner:OwnerSessionHostRef, mirrorId:string, worktreeId:string, instanceId:string, fingerprint:string}`. Resolve only from remoteList/remoteRefresh. Require exact mirror/host/generation/canonical-worktree/instance/fingerprint identity, and revalidate the producer worktree instance immediately before the target side effect. A mirror is never a local worktree selector.

**Accounts:** preserve local public methods unchanged. Add one schema-declared scoped dispatch method `ownerCall` accepting `owner:OwnerSessionHostRef`, a fixed `operation` enum and `params` object. Its whitelist contains only the actual Accounts/Usage/Agents operations needed by its own UI; it is not an arbitrary remote RPC proxy. Browser login, reauthentication, pending-link opening and local-only switch-policy mutation are rejected remotely. Renderer scope changes clear incompatible data and invalidate every in-flight request/revision/event. Local UI preferences are local. UI exposes the selected host and maintains exact-window focus isolation. CLI exposes the scoped method via its existing group.

**Vault provider:** ship a real `vault-host` contribution in the Vault manifest. Extend its discovery contract to enumerate canonical registered owner hosts dynamically; the static contribution itself is not one host credential or authority. Preserve existing third-party/static contribution compatibility; all actual remote requests resolve and compare a full owner binding. Its method routes are explicitly declared in the production manifest. Production integration tests install no forwarding fixture.

**Vault actions:** get/firstPrompt/subagents/resume/handoff accept existing opaque host-qualified IDs. Resolve source only on the selected owner; requalify child IDs, strip remote source paths/codexHome/launch environment/resume command, and preserve partial host failures. Resume requires a selected exact registered workspace on that source owner and target-side instance validation. Nonlocal copy-command/system-open/reveal/Trash remain refusals. All-host enable executes local first, then each host sequentially with separate outcome receipts.

**Vault→Handoff shared contract:** existing `quirky.handoff/openArchived` source remains `{archived:{agent,...}}`. Add optional `archived.owner:OwnerSessionHostRef` and `archived.vaultId:string`; vaultId is the opaque owner-local Vault ID (the form accepted by quirky.vault/get on that owner), never a path. When owner is present, Handoff resolves authoritative source metadata on that exact owner using the existing public Vault get API; caller archived paths/cwd/provider IDs are not authority. Vault passes sanitized display metadata plus this owner-local ID, not credentials or raw paths. Handoff opens the local window review dialog, not a remote headless UI command. Without owner, current local callers are unchanged. Both slices implement this exact contract before integration.

**Handoff targets:** keep local worktree/create target semantics; add owner workspace target shape `{remote:OwnerSessionWorkspaceRef}`. Candidates, controls/schema, CLI and UI use that exact shape. Enumerate registered remote mirrors alongside local candidates, visibly qualifying host names. Remote detection/probe/start/delivery invoke explicit schema-declared target-side Handoff endpoints over pinned runtimeCall; they are not arbitrary method proxies. Target-side validation requires exact canonical worktree ID plus expectedInstanceId and enabled/detected agent before launch. Remote transcript source lookup uses owner-local Vault ID or verified provider roots on that host, never a caller's local path as reachability proof. Full transcript requires positive target-side validation. Cross-host source/target distinction feeds existing secret scan/warnings. Remote resend remains tied to the launched host/workspace/session and original reviewed brief, without a second automatic uncertain send.

**Lineage:** ends add execution-host identity (local producer identity for local ends; registered owner host for remote ends) and instance identity when known. Historical host identity records are provenance, not current action authority. Legacy local records remain valid, but never match remote records by bare provider/session/worktree ID. Jump verifies host/generation before routing and never focuses an identically named local session for a remote end.

## Data models / schemas
For [S1–S7](logic.md#behavior-and-acceptance-scenarios), public method schemas use the supported protocol/schema.ts subset (no unions/refs/nullable type arrays). Runtime guards enforce mutually exclusive variants, exact keys and safe bounds. Shared protocol reference types are data-only and committed before feature implementers; each feature owns its declared method schemas and renderer parsers. Existing rows remain readable; new lineage host fields are additive provenance with explicit legacy-local interpretation. No credential or raw remote launch environment enters public feature DTOs.

## DO-NOT-CHANGE fences
For [scope](logic.md#scope-and-non-goals):
- `plugins/quirky.cli/main.ts` callOwnerRuntime scope/pin checks and encrypted pairing transport: canonical authority, no changes needed.
- `plugins/quirky.worktree/src/daemon/remote.ts` canonical mirror/instance/remove/cleanup/navigation checks: authority producer, no bypass or path-based extension.
- `docs/loop/LOOP.md`, `scripts/build-loop/`, `docs/loop/queue.json`, `docs/loop/DECISIONS.md`: protected/controller-owned.
- Phone/federation admission, native chat, signing/OS capabilities: not this feature's authority or scope.
- Existing local provider roots/account profiles/indexer/terminal readiness and one-use confirmation: preserve; change only on demonstrated consumer-visible failure required by these flows.

## Always / Ask / Never
For [Decisions Locked](logic.md#decisions-locked): always validate complete current pins, preserve scope epochs/revisions, local-first policy ordering, redaction and explicit uncertainty. Resolve choices autonomously and record them. Never ask a human, run a direct bun test, modify real user homes, infer local authority from remote paths, use synthetic production credentials, disable consumer assertions or relax timeouts to hide failures.

## Cross-cutting
For [S7](logic.md#s7-authority-and-defect-boundaries): error messages exposed across feature boundaries redact filesystem/credential material. Graceful availability is not a fallback. Ephemeral remote calls close their connections; owner daemon/session resources are cleaned by exact activation/test owner. No migration to phone/worker credentials. Existing local-only APIs remain compatible; the change is a clean new host-qualified path, not deprecated aliases. New failure modes remain explicit to consumers and draft-preserving.

## Testing strategy
For [S1–S7](logic.md#behavior-and-acceptance-scenarios), each feature owns its new behavior tests. Real isolated local and remote daemon kernels with owner pairing, saved runtime registration and actual worktree registration/mirrors prove operation placement and stale/refused actions; fixtures provide private native-format accounts/transcripts and controlled provider executables, never production forwarding plugins. Check selected remote account changes while local bytes remain intact; remote-only Vault get/resume; target-side handoff brief bytes, source liveness and host-qualified lineage; generation/grant/instance/phone-scope refusal before side effects. Renderer tests cover exact-window scope, stale replies, sign-in gates and remote target controls, not wording/style/source mirrors.

**COMMAND:** `bun scripts/suite.ts plugins/quirky.accounts plugins/quirky.vault plugins/quirky.handoff packages/protocol plugins/quirky.cli plugins/quirky.worktree scripts` must pass, with exact runner retries/flakes reported. Parent also runs `bun run typecheck` and `bun run build`, then an actual isolated paired-daemon/API/CLI/PTY smoke through suite.ts and supported web UI scenario via using-apps-like-a-user. If its tool cannot run under the operator's runner policy, record attempted tool failure and exact missing visual evidence instead of fabricating a pass. Native-only browser/OS scenarios remain pending handoff where relevant. Final checks after the single canonical catch-up precede one independent cross-family final discovery/fix round.
