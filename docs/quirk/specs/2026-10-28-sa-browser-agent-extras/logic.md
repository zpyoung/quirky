## Goal and conceptual model
Complete sa-browser-agent D38's deferred backend flows on the current Browser plugin. A managed profile owns durable Chrome data and one helper; a page owns an exact epoch-bound helper/CDP identity. API and CLI consumers use the same schema-declared operations. Cookie sources are read-only; only an explicitly selected managed destination changes. Human Native panes and agent Chrome are distinct engines; importing Chrome cookies does not claim to import into WKWebView.

## Scope and non-goals
In scope: explicit source discovery, Chromium/Firefox/Safari/JSON cookie import and tracked jobs, cookie/storage CRUD, remaining profile show/default/switch/clone, history navigation, advanced interaction/keyboard/find/mouse/upload/download, full capture/PDF, network/console/HAR/interception, emulation/headers/auth/media/offline/geolocation, private headless clipboard and dialogs, and explicit CLI bulk input. Existing Chrome identity setting and native profile-clear restrictions remain canonical. Native clear/delete completion, native UA overrides, remote/SSH/client-host routing, artifact publishing and design-mode presentation belong to their existing owners; do not duplicate those queue items. Import menus, file picker, badges and summary/error toasts belong to the existing dependent `sa-browser-profile-import-ui`, not this engine item.

## Decisions locked and alternatives
- API/CLI: existing authenticated quirky.browser methods, stable browser reason prefixes, normal CLI errors; no second transport. Recover focused archive code rather than replace current runtime or reimplement every helper feature from scratch.
- Targeting: explicit page/worktree for mutations, profile FIFO across select plus complete operation, projected ephemeral refs; never global mutation fallback, raw helper IDs, blind native command forwarding or implicit mutation replay.
- Data: explicit detection only after import UI opens or API/CLI request; no protected-source startup reads. Replace only safely imported registrable families, private PSL included. Google cookies are excluded. Unreadable partition families are not deleted. Exact cookie identities include hostOnly/path/partitionKey. Roll back before reporting replacement failure; disclose unprovable rollback as browser_unsafe_replace. No plaintext restart staging fallback: live CDP success or explicit failure, never false durable success.
- Profiles: retain current profileSet pane contract and profileDelete/ProfileLifecycle guard. Page-level profile selection uses distinct tabProfileShow/tabProfileSet/tabProfileUseDefault methods; `tab profile set-page` avoids colliding with existing `tab profile set --pane`. Clone copies real cookies to an empty isolated destination, never a live native partition. Imported-source metadata is optional on existing records and persisted only after successful import.
- CLI: strings remain literal, including @file:. Explicit --value-file/--expression-file/--text-file or a single corresponding --*-stdin flag read data only for the named field, mutually exclusive with inline data. File cookie import uses explicit absolute source.path (CLI --file). Never read page-provided instructions as files/commands. Browser-file JSON remains daemon-local; selected UI file bytes use explicit validated JSON contents, not a fabricated host path.
- Interaction errors remain visible; no successful unavailable/no-op methods. Dialog answering uses exact-session out-of-band CDP so pending evaluate/prompt cannot deadlock the profile FIFO. Network interception and HTTP auth compose with the current Watch prompt path rather than installing competing event handlers.
- macOS only. Linux/Windows decryption/roots/process verification is deferred: platform. Tests use fresh ProcessScope homes, synthetic source roots/keys, mock-keychain Chrome, local HTTP fixtures, and owned cleanup only.

## Behavior and acceptance criteria
Each SC is exercised through daemon API or actual CLI by authored acceptance tests; boundary algorithms additionally receive deterministic regressions. Existing pane/design/profile behavior must remain unchanged.

### SC1 — Explicit discovery and source reads
Before: plugin enabled, synthetic browser roots configured, no Chrome running. Listing profiles/preferences does not inspect sources/start Chrome. Explicit detectBrowsers lists only sources with actual cookie files, with safe profile names. Chrome/Edge/Arc/Brave/Comet/Helium use selected Local State profiles; Firefox and Safari use their actual formats. Traversal profile names fail before reads. Source DB and WAL snapshots are stable/retried boundedly and cleaned; browser-specific permission/locked-file errors are actionable. Source bytes are unchanged afterward.

### SC2 — Transactional import and jobs
Before: destination has old example.test login plus unrelated other.test login. Import source example.test new login, google.com and unreadable partition family: replace safe example.test identities only, keep other.test and skipped families, disclose counts/warnings without cookie values. Inject a failed write: original identities/values return; rollback failure is explicit unsafe replacement. File sources reject malformed/nonarray/empty/no-valid data without mutations. v10/v11 macOS decryption handles schema24 host digest faithfully; unsupported v20/undecryptable rows warn rather than delete their families. Firefox expired rows and Safari binary timestamps/flags are handled. importStart immediately returns a job ID; get/list report queued/running/succeeded|failed, destination and summary, shutdown cancels and drains owned work. Reimport is idempotent in visible cookie state.

### SC3 — Direct cookies and storage
Before: two profiles/pages, same origin, distinct identities. Cookie set/get/exact delete and local/session get/set/clear alter only the requested target. Secure/SameSite/expiry/partition identities survive roundtrip; ambiguous delete is refused. Storage values are literal, including empty, Unicode and @file:. Session storage stays page-local; local storage stays origin/profile-local. Irreversible methods require yes/normal dispatcher confirmation.

### SC4 — Profiles and identity
Before: two isolated profiles and page P at U in A. tabProfileShow returns A; tabProfileSet B rebinds P safely at U, clears refs, leaves neighboring pages/panes unchanged; use-default selects Default. Clone from P into unused isolated C copies actual cookies and creates an independent page at U; nonempty destination is rejected, partial failure rolls back. Current pane profileSet and native-completion-rejecting profileDelete remain unchanged. identityGet/Set, if exposed, route the existing setting with next-runtime semantics, never return success-shaped ineffective state.

### SC5 — History, interactions and semantic locators
Before: local HTML form and links. back/forward/reload reflect actual URLs/title; navigation invalidates refs. dblclick/type/inserttext/keypress/select/check/uncheck/focus/hover/scrollIntoView/clear/selectAll/drag/upload/scroll/wait/get/is/find and mouse operations visibly affect the exact page. Text >8KiB is delivered without argv expansion. nth uses explicit signed32-bit index with CSS value, zero first/negative from end; index on other locator kinds is invalid. Wait predicates respect timeout and hidden state; timeout returns browser_timeout. Upload uses explicit files, download returns bytes or a real owned output path. No implicit OS opener/focus.

### SC6 — Capture and observability
Before: fixture taller than viewport and a local request endpoint. Full screenshot captures full document; viewport capture stays viewport; PDF decodes to %PDF. console/network obey limit and preserve actual entry data. HAR start/stop captures actual requested URL/status/content sizes, not an empty synthetic archive. Enable two intercept patterns, list both, observe both, disable prevents future collection/routing; preserve settings after owned epoch reconstruction. Auth/Watch handling never answers another page's pending challenge.

### SC7 — Emulation and control
Before: current page and untouched neighbor. viewport/device/geolocation/offline/headers/credentials/media affect actual browser JS/network and survive permitted page reconstruction. Clipboard read/write roundtrip the real private headless clipboard; >8KiB write rejected, OS clipboard untouched. Evaluate a pending prompt/confirm then dialogAccept/ Dismiss: exact pending page resolves with supplied Unicode/false while neighboring page unchanged. Missing/stale dialog fails; no FIFO deadlock.

### SC8 — Public API/CLI and explicit bulk data
Before: inline @file:path and existing synthetic file. Inline fill preserves the literal string. Explicit named file/stdin mode delivers file bytes exactly, mutual inline/file/stdin combinations are usage errors before RPC. API catalog, CLI and exec expose only implemented typed methods; lifecycle/target override flags are rejected by exec. The dependent import UI receives real detectBrowsers/importCookies/importStart/Get/List and JSON-cookie source contracts, with selected destination and actual summary/error state. This item does not scan sources on mount or fabricate Native/WKWebView import capability; visible menu integration remains with its existing owner.

### Runtime integration signatures
Runtime component supplies `setPageProfile(page: BrowserPage, profileId: string): Promise<BrowserPage>` and `clonePageProfile(page: BrowserPage, destinationId: string): Promise<BrowserPage>`; the latter returns the new independent page. These own sorted multi-profile locking internally, close/Watch cancellation and rollback; callers must not wrap them in another runtime lock. Runtime `answerDialog(pageId: string, accept: boolean, text?: string): Promise<void>` runs out of band. Cookie component supplies BrowserStore `setPageProfile(pageId: string, profileId: string): BrowserPage` (metadata only) and `markImported(profileId: string, source: {browserFamily:string; profileName?:string; importedAt:number}):void` after successful import. BrowserProfile gains optional `source` metadata and `imported` scope, retaining read compatibility with old records. Surface calls importer `importCookies(profileId|undefined, source)`, `start(profileId|undefined,source)`, `get(id)`, `list(profile|undefined,status|undefined)`, and `await cancelAll()` on deactivate.
