## Architecture
Trace: [conceptual model](logic.md#conceptual-model), [key decisions](logic.md#key-decisions--rationale).

Create the built-in `plugins/quirky.browser` workspace. Runtime is Bun; npm dependencies `agent-browser` exactly 0.27.0 and `tldts` exactly 7.4.16. The plugin uses only `@quirky/protocol` public types and `PluginContext` plus ordinary trusted Bun/Node filesystem/process/network APIs. No Electron or private daemon/worktree module imports. Chrome is discovered from a configured executable or standard macOS installation, not bundled. Missing executable returns an actionable error, not a mock browser. The helper package's native platform binary contains its daemon runtime and must ship in the desktop distribution; no runtime path may depend on the upstream checkout.

One component implements the full vertical feature (automation, profile/import coordination, schema API/CLI, tests and packaging). This avoids speculative interfaces between cookie policy, Chrome lifecycle, per-profile mutation locking and API targeting. Its internal modules retain separate responsibilities below. A single component/single wave has no non-final checkpoint; final three-lens review covers the whole branch. Read-only source surveys are separate from implementation ownership.

### Native dependency packaging
Trace: [SC-18](logic.md#sc-18-clicatalog-and-distribution).

Use private plugin `package.json` build metadata, not runtime `quirky-plugin.json` fields: `quirky.assets` is an array of `{dependency:string,source:string,destination:string,executable?:boolean}`. Resolve only dependencies declared by that plugin, using package resolution from its directory; source is relative to the resolved dependency package directory, destination relative to the plugin output directory. Permit only `{platform}` and `{arch}` placeholders from the current build host. Reject absolute/traversing source/destination paths, symlink escapes, unknown placeholders and collisions with manifest/bundled entry outputs. Missing declared assets fail the build. Copy exact bytes and set executable mode when requested. No arbitrary build hooks or commands.

Browser package declares agent-browser `bin/agent-browser-{platform}-{arch}` to `bin/agent-browser` with executable true. Its runtime resolves the packaged sibling `bin/agent-browser` first; in source development only, resolve the pinned dependency from the plugin package. Neither path consults upstream Orca, PATH helpers or real agent homes. Current distribution build host is macOS arm64; cross-building to a different host target and Linux musl/Windows native asset verification are explicitly deferred platform work, not claimed supported here.

CONFIG: `QUIRKY_BROWSER_CHROME` is the optional absolute Chrome/Chromium executable path; otherwise discover standard macOS Chrome/Chromium installation paths. This config is inspected only when a browser operation requires launch. Invalid explicit executable fails with browser_unavailable and an actionable config remedy; no automatic download or unrelated browser attachment.

Only this locked driver writes to the private socket; page content/public exec cannot send native actions directly. Native tab requests do not auto-launch Chrome. Metadata reads do not start Chrome; helper-backed reads use the same lock. A dead child, socket EOF, malformed response or transport timeout invalidates the epoch and all mappings/refs before any next dispatch, rejects triggering work without retry, and closes owned processes outside the blocked FIFO. The next explicit browser operation starts fresh owned Chrome/helper against the same durable profile and recreates retained managed pages from saved URLs via newly returned IDs, matching logic.md's recovery amendment. No order/URL/title/tN-reuse inference or discovered unmanaged-page adoption is allowed.

Operations spanning two profiles (`profileSet`, `profileClone`, profile deletion reassignments) acquire distinct profile locks in ascending profile-ID order; never recursively enqueue work behind a lock already held. Queue entries bind public page ID, owning profile and page generation; revalidate after acquiring locks and reject changed/closed pages before executing. Closing marks/cancels relevant work immediately outside the FIFO, then performs bounded owned cleanup. A profile-wide epoch failure rejects or revalidates every queued entry; it cannot dispatch an old tN after reconstruction.

Chrome uses `--headless=new`, private user-data-dir, loopback-only ephemeral debugging, and no sandbox/TLS weakening. Clear inherited AGENT_BROWSER target/profile/args/config variables and isolate helper HOME/config as well as sockets. Shutdown explicitly detaches/closes helper and closes Chrome, bounds waiting, then signals only retained owned child/process groups if needed; helper `close` alone does not stop externally attached Chrome. Total deactivate cleanup must fit the existing 10-second host bound. ### Trusted page binding and dialog control
Trace: [dialog-control amendment](logic.md#status--amendments), [SC-07](logic.md#sc-07-network-console-and-emulation).

Create every managed helper page initially at `about:blank`, without opener and before any caller URL/content executes. Under the profile lock, attach direct flattened CDP sessions to owned candidate page targets and record their trusted sessionId/targetId association; enable Debugger and start consuming scriptParsed events before challenging the helper-selected fresh blank page. Ask native evaluate to execute only primitive `null` followed by a sourceURL comment containing a cryptographically random single-use label. Bind the selected public page/tN to the one direct CDP session emitting that exact new `Debugger.scriptParsed` label. Require exactly one match in the current browser/helper epoch; missing, duplicate, stale, malformed or unexpected-page matches fail closed and tear down the new page/epoch. Disable Debugger after binding and only then navigate to the caller URL. No page URL/title, target ordering, global JS property marker, arbitrary existing-page rebinding, or persisted old session mapping is used. SourceURL here is trusted debugger metadata for a non-throwing primitive script on a fresh blank page, never page-provided data.

Retain `{browserEpoch,pageGeneration,targetId,sessionId}` internally; subscribe `Page.javascriptDialogOpening/Closed` on the bound direct session. Configure native helper `AGENT_BROWSER_NO_AUTO_DIALOG=1` so it cannot race the direct controller. `dialogAccept`/`dialogDismiss` are the only normal-command-lock exception: resolve an explicitly scoped page, require its current exact pending dialog event and live epoch/generation, then send `Page.handleJavaScriptDialog` on that already-bound direct session. They never select another helper tab, launch a process, or wait behind the blocked operation. Revalidate the binding after response; missing pending dialog returns `browser_error`, changed/closed binding returns the corresponding changed/closed error, never success on another page. Concurrent duplicate responses serialize against the pending-dialog token; one succeeds, later responses fail. Close/profile switch/epoch death invalidates pending tokens immediately.

Normal evaluation remains pending until the dialog is answered and returns its real result, or its ordinary bounded timeout/close error occurs. Unanswered dialogs are not silently accepted. SC-07 must exercise eval awaiting Unicode prompt acceptance and confirm dismissal on separate managed pages, including wrong-page/no-dialog refusal. Actual fresh-blank handshake and out-of-band prompt/confirm handling were exercised with 29 assertions in `/tmp/quirky-browser-lane5-dialog-binding-smoke.json`; this is feasibility evidence, not the permanent API acceptance suite.


### Failure transport
Trace: [decisions locked](logic.md#decisions-locked), [SC-10](logic.md#sc-10-lifetime-and-failure).

Use public `ctx.error(kind,message)` and the existing JSON-RPC error envelope, never a success-shaped failure result. Public plugin errors support only `invalid-params`, `not-found`, and `conflict`; no browser-specific `error.data` field is promised. Every browser operational failure message begins with a stable `reason: ` prefix. `invalid_argument`, `browser_import_invalid_json`, `browser_import_not_array`, `browser_import_empty`, `browser_import_no_valid_cookies` map to `invalid-params`; `browser_no_tab`, `browser_tab_not_found`, `browser_profile_not_found`, `browser_import_not_found` map to `not-found`; `browser_stale_ref`, `browser_tab_closed`, `browser_tab_changed`, `browser_timeout`, `browser_eval_error`, `browser_unavailable`, `browser_import_source_unavailable`, `browser_unsafe_replace`, and `browser_error` map to `conflict`. Reasons are machine-readable prefixes, not new RPC numeric codes. Schema validation failures retain the ordinary dispatcher behavior before the handler.

RPC failures use the existing numeric `RpcErrorCode` for their kind and a message containing that prefix. Custom CLI forwards RPC failures to existing top-level handling: `--json` emits the existing `{error:{code,message}}` object to stdout and exits 1; human mode emits `quirky: <message>` on stderr and exits 1. Local CLI usage/argument failures exit 2. Never catch and print a browser failure as a successful command. Missing Chrome names the configured/discovered executable remedy without leaking credential paths. Import job errors store only `{code:<stable reason>,message:<redacted human message>}`; a failed synchronous import throws the same RPC failure instead of returning a summary.

Ref mapping is generation-aware: navigation, profile switch/tab switch/page close invalidate previous refs, including when helper internally reuses e1. Raw selectors can be accepted where source commands allow them; refs must be validated against the current page snapshot generation before invoking the helper. Exec must reject target/session/profile/launch override flags and tab/browser/session lifecycle commands, not merely strip a flag and then forward a retargeting command. Shell command interpolation is prohibited.

Default command timeout 90s, navigation at most 30s, reload at most 10s, helper close at most 5s; condition wait timeout = requested timeout plus bounded transport overhead. Bound captured output to 50 MiB and terminate owned children on overflow/timeouts/cancel. Fill/eval carry large exact strings through native socket JSON, never argv or shell interpolation; typing chunks retain Unicode scalar boundaries and ordering. `selectAll` uses platform-correct selection. Captures read only owned generated output files and delete them in finally; user-directed download paths remain files owned by the request.

### Import contract

Required strings are nonempty except the explicitly empty-capable `fill.value`, `cookieSet.value`, `storage*.value`, `setCredentials.pass`, and `dialogAccept.text`. Finite numeric fields reject NaN/infinity; integer fields must be integral. An omitted optional field is absent (not `null`) unless a default is stated below. `cwd` is a canonical absolute directory path supplied by the CLI from `CliContext.cwd`; there is no `--cwd`. A CLI option named `--label` maps to API `name`; `--scale` maps to API `deviceScaleFactor`; `--element` maps to API `element`; cookie/profile IDs are API fields named `profile`.

Every CLI path below is inside `quirky browser ...`, except import paths which are listed in the existing Import contract. Preserve source word spelling and dashes (`full-screenshot`, `select-all`, `scrollintoview`, `inserttext`, `open-url`). `--json` is available on every path and is opt-in; omitted means the existing human formatter. Every method accepting `PageTarget` also exposes `--page <id>` and `--worktree <selector>` even where its row omits the common flags. The CLI adds `cwd` from `CliContext.cwd`; no `--cwd` flag. `all` is accepted only on read-only list/filter commands, not as a concrete command target. `--yes` is available for manifest-destructive methods and uses existing dispatcher confirmation behavior.

Target resolution is inherited by every `PageTarget` method: an explicit `page` public ID takes precedence over `worktree`/`cwd`; an invalid explicit ID fails and never falls back. `worktree` accepts the worktree plugin's ID/name/branch/path/current selectors and uses the existing canonical longest-root cwd resolution. For reads only, absent scope may select the sole/global active managed page; otherwise return `browser_no_tab`. Mutations (including input, storage, cookie, route, emulation, profile, and tab changes) require an explicitly resolved managed page/profile and never use a global active-page fallback. `worktree:'all'` is never a mutation target. Tab/profile metadata list/show methods do not start Chrome. Browser input and capture are page-scoped; cookies are profile-scoped and resolve the page's owning profile. Every helper-backed operation, including multi-step calls and profile changes, runs under the owning profile FIFO lock from the existing topology contract.

Selector/reference contract: `element` and `selector` fields accept a current `SnapshotRefToken` or a CSS selector only for commands whose source surface accepts selectors (`click`, `dblclick`, `fill`, `select`, `check`, `uncheck`, `focus`, `hover`, `scrollIntoView`, `clear`, `selectAll`, `drag`, `upload`, `get`, `is`, `wait`, `highlight`, `download`). `find` uses its semantic locator fields, not a ref. `snapshot` mints one UUIDv4 `projectionId` per returned projection and public refs of the form `qbr1:<projectionId>:<1-based-node-index>`; the private mapping binds each token to exactly one `{browserPageId,projectionId,helperLocalRef}`. Raw helper refs such as `@e1` are never public and are rejected as stale refs, not reinterpreted as CSS. A token is accepted only for its exact page and current projection. Navigation, tab switch/close, profile switch, helper-epoch loss, and a later snapshot invalidate the prior projection. Old tokens always fail `browser_stale_ref`; they can never alias a reused helper-local ref.

`profileSet` changes the profile binding of the selected public page while preserving its public `browserPageId` and URL; its new helper tab is created in the destination profile's one-helper-per-profile process.
